# دليل النشر — AqarTech

هذا الدليل لنقل المنصة من جهازك (localhost) إلى الإنترنت بدومين حقيقي. يُنشر جزآن:

| الجزء | ما هو | أين يُستضاف |
|---|---|---|
| **الخادم** (`backend/`) | NestJS + قاعدة بيانات PostgreSQL | أي استضافة تشغّل Node.js 20 أو أحدث، مع PostgreSQL مُدار |
| **الموقع** (التطبيق نفسه على الويب) | ملفات ثابتة تنتج من `npx expo export -p web` | أي استضافة مواقع ثابتة (Cloudflare Pages، Netlify، Vercel، أو نفس خادمك عبر nginx) |

تطبيقات الجوال (App Store وGoogle Play) لها مرحلة مستقلة (المرحلة 9)، وتستخدم **نفس الخادم**.

> اقتراح للأسماء: `aqartech.om` للموقع، و`api.aqartech.om` للخادم.

---

## 1. قبل البدء

- **دومين** تملكه، مع إمكانية إضافة سجلات DNS.
- **HTTPS** إلزامي للموقع والخادم. معظم الاستضافات توفره مجاناً.
- **قاعدة PostgreSQL** مُدارة، مع نسخ احتياطي يومي.
- **صندوق بريد للإرسال (SMTP)** لرموز «نسيت كلمة المرور».

## 2. الخادم

### المتغيرات (`backend/.env` على الاستضافة)
القائمة الكاملة موجودة في `backend/.env.example`. ⚠️ لا تضع القيم الحقيقية في GitHub، ولا ترسلها لأحد.

| المتغير | القيمة في الإنتاج |
|---|---|
| `DATABASE_URL` | رابط قاعدة الإنتاج |
| `JWT_SECRET` | نص عشوائي جديد طويل، ليس نفس قيمة جهازك |
| `ADMIN_2FA_KEY` | نص عشوائي طويل آخر. **لا يتغير بعد ذلك أبداً** |
| `CORS_ORIGINS` | `https://aqartech.om` (عنوان الموقع فقط) |
| `PORT` | حسب الاستضافة |
| `SMTP_*`، `MAIL_FROM` | بيانات البريد |
| `SUBSCRIPTION_GRACE_DAYS` | أيام السماح بعد انتهاء الاشتراك (افتراضياً 3) |
| `ADMIN_EMAIL`، `ADMIN_PASSWORD` | لأول حساب أدمن فقط (عند `db:seed`) |
| `SEED_DEMO` | **0** في الإنتاج |
| `UPLOAD_DIR` | مجلد المستندات المرفوعة على **قرص دائم** (لا يُمسح عند إعادة النشر)، مثل `/var/aqartech/storage` |
| `OCR_DATA_DIR` | اختياري: مجلد ملفات لغة محرك القراءة (افتراضياً `backend/ocr-data`) |

لتوليد نص عشوائي:
```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

### أوامر التشغيل
```bash
cd backend
npm ci                      # يجهّز محرك القراءة تلقائياً (ينزّل ملفي اللغة مرة واحدة)
npm run ocr:setup           # للتأكد: يجب أن يطبع "OCR engine ready"
npx prisma migrate deploy   # يطبّق كل التحديثات على قاعدة الإنتاج (لا تستخدم migrate dev هنا)
npm run build
npm run db:seed             # مرة واحدة فقط: ينشئ أول حساب أدمن
npm run start:prod
```

عند كل تحديث لاحق:
```bash
git pull
npm ci
npx prisma migrate deploy
npm run build
```
ثم أعد تشغيل الخدمة.

## 3. الموقع

1. في مجلد التطبيق الرئيسي، أنشئ ملف `.env` (أو أضف السطر إلى ملفك) بعنوان الخادم:
   ```
   EXPO_PUBLIC_API_URL=https://api.aqartech.om
   ```
2. ابنِ الموقع:
   ```bash
   npx expo export -p web
   ```
   الناتج يكون في مجلد `dist/`.
3. ارفع محتوى `dist/` إلى استضافة المواقع:
   - **Cloudflare Pages / Netlify:** ارفع `dist`. الملف `public/_redirects` يُنسخ تلقائياً، ويجعل روابط مثل `/tenants` تعمل عند تحديث الصفحة.
   - **Vercel:** أضف `vercel.json` فيه إعادة توجيه كل المسارات إلى `/`.
   - **nginx على خادمك:**
     ```nginx
     location / {
       root /var/www/aqartech;
       try_files $uri /index.html;
     }
     ```
4. اربط الدومين بالاستضافة، وفعّل HTTPS.

## 4. بعد النشر مباشرة ✅

- [ ] ادخل بحساب الأدمن، وغيّر كلمة المرور الأولى من «الإعدادات».
- [ ] **فعّل الدخول بخطوتين لحساب الأدمن:**
  1. «الإعدادات» ← «الدخول بخطوتين» ← «تفعيل».
  2. أضف المفتاح في Google Authenticator أو Microsoft Authenticator.
  3. اكتب الرمز.
  4. **احفظ رموز الاسترداد الثمانية** في مكان آمن.

  افعل ذلك لكل عضو في الفريق أيضاً.
- [ ] تأكد أن `SEED_DEMO=0`، ولا توجد شركة تجريبية.
- [ ] جرّب «نسيت كلمة المرور» للتأكد أن البريد يُرسل.
- [ ] جرّب الموقع على الكمبيوتر والجوال، وحدّث صفحة داخلية مثل `/tenants` للتأكد أن الروابط تعمل.
- [ ] من صفحة «النشر» تأكد أن الإعداد منشور (النسخة 1 على الأقل).
- [ ] فعّل **النسخ الاحتياطي اليومي** لقاعدة البيانات، وجرّب الاسترجاع مرة.
- [ ] اجعل النسخ الاحتياطي يشمل **مجلد المستندات** (`UPLOAD_DIR`) مع قاعدة البيانات.
- [ ] من قسم «المستندات» جرّب «قراءة مستند» بصورة بطاقة أو شيك (يجب ألا تظهر رسالة «غير مجهّزة»).

---

## 5. ملاحظات

- إذا نقلتَ قاعدة بيانات جهازك نفسها إلى الإنتاج مع **نفس** `ADMIN_2FA_KEY`، يبقى الدخول بخطوتين يعمل. أما مع مفتاح مختلف، فيُعاد تفعيله.
- لا ترفع ملفات `.env` إلى GitHub. هي مستثناة في `.gitignore`.
- الموقع يعمل كتطبيق صفحة واحدة: ملف `index.html` واحد، والروابط تُدار داخل التطبيق.
